## 二、项目概述

### 2.1 项目一句话描述

打造一个面向高校学生和社团组织的一体化校园活动管理平台，覆盖活动发布、在线报名、扫码签到全流程。

### 2.2 选题动机（解决谁的什么真问题）

- **学生痛点**：校园活动信息分散在各个微信群、公众号，学生难以及时获取感兴趣的活动；报名流程繁琐，需要填多个问卷；线下签到靠人工点名，排队时间长。
- **社团痛点**：活动发布渠道分散，报名数据统计效率低；签到靠人工，容易代签；活动结束后缺乏数据沉淀和效果分析。

### 2.3 项目边界（本期做/不做）

**本期做：**

- 活动列表展示与分类筛选
- 活动详情查看与在线报名
- 我的活动管理（待参加/已结束）
- 扫码签到功能
- 简单的活动发布后台

**本期不做：**

- 活动评价与反馈系统
- 积分与荣誉体系
- 活动推荐算法
- 支付与报名费管理

## 三、目标用户分析

### 3.1 目标用户群体

1. **在校学生**（主要用户）

   - 人数：约2000人（本校学生）
   - 特征：熟悉手机操作，喜欢参加各类校园活动
   - 需求：快速发现活动、便捷报名、高效签到

2. **社团/组织管理者**（次要用户）

   - 人数：约50个社团
   - 特征：需要管理活动报名和签到数据
   - 需求：高效发布活动、实时掌握报名情况、快速完成签到

### 3.2 用户场景

- **场景1**：学生在食堂看到海报，扫码打开活动平台，浏览并报名感兴趣的讲座
- **场景2**：社团负责人在活动开始前，打开后台查看报名人数，生成签到二维码
- **场景3**：学生到达活动现场，打开"我的活动"，出示签到码完成签到

## 四、需求分析（NABCD框架）

### 4.1 N - 需求（Need）

| 用户类型 | 核心需求          | 痛点程度 |
| ---- | ------------- | ---- |
| 学生   | 一站式发现校园活动     | 高    |
| 学生   | 快速报名，不用填多个问卷  | 高    |
| 学生   | 扫码签到，不用排队点名   | 中    |
| 社团   | 高效发布活动，统一管理报名 | 高    |
| 社团   | 实时掌握报名人数和到场情况 | 中    |
| 社团   | 活动数据统计与分析     | 中    |

### 4.2 A - 做法（Approach）

- **移动端优先**：采用手机端H5设计，学生无需下载APP，浏览器直接使用
- **一体化闭环**：从活动发布→报名→签到→数据统计，全流程在一个平台完成
- **轻量化架构**：前后端分离，快速迭代，适合学生项目开发节奏

### 4.3 B - 收益（Benefit）

- **学生端**：活动信息获取效率提升60%，报名签到时间从5分钟缩短到30秒
- **社团端**：活动管理效率提升50%，签到统计时间从20分钟缩短到2分钟
- **学校端**：校园活动数据可视化，便于整体规划和资源调配

### 4.4 C - 竞争（Competition）

| 对比项  | 现有方案（微信群+问卷星+人工点名） | 我们的系统     |
| ---- | ------------------ | --------- |
| 信息整合 | 分散在多个渠道            | 一站式聚合     |
| 报名效率 | 手动统计，易出错           | 自动统计，实时更新 |
| 签到方式 | 人工点名，易代签           | 二维码签到，防代签 |
| 数据沉淀 | 无，活动结束就丢失          | 完整数据记录与分析 |

### 4.5 D - 推广（Delivery）

- **第一阶段**：在本小组所在班级试点，收集反馈
- **第二阶段**：与2-3个学生社团合作推广
- **第三阶段**：面向全校学生和社团开放

## 五、用例模型

### 5.1 参与者（Actor）

1. **学生**：浏览活动、报名活动、签到活动、管理个人活动
2. **社团管理员**：发布活动、管理报名、查看签到数据
3. **系统管理员**：管理用户、审核活动、系统配置

### 5.2 主要用例

#### 学生用例

| 用例编号 | 用例名称   | 描述                     |
| ---- | ------ | ---------------------- |
| UC01 | 浏览活动列表 | 学生查看所有可报名的活动，可按分类筛选    |
| UC02 | 查看活动详情 | 学生查看活动的详细信息，包括时间、地点、介绍 |
| UC03 | 报名活动   | 学生选择活动，填写信息完成报名        |
| UC04 | 取消报名   | 学生在活动开始前取消已报名的活动       |
| UC05 | 扫码签到   | 学生到达活动现场，出示签到码完成签到     |
| UC06 | 查看我的活动 | 学生查看自己报名的所有活动，分类展示     |

#### 社团管理员用例

| 用例编号 | 用例名称   | 描述                  |
| ---- | ------ | ------------------- |
| UC07 | 发布活动   | 管理员填写活动信息，发布新活动     |
| UC08 | 管理报名   | 管理员查看报名列表，审核或导出报名数据 |
| UC09 | 生成签到码  | 管理员为活动生成签到二维码       |
| UC10 | 查看签到统计 | 管理员查看活动的签到情况和到场率    |

## 七、AI协作约定

1. **AI参与环节**：需求梳理、原型设计、代码起草、文档整理
2. **人负责环节**：需求决策、方案拍板、质量验收、最终交付
3. **交叉验证机制**：AI生成的代码和文档由人工逐一审查，禁止"谁生成谁验收"
4. **原则**：AI是协作者不是枪手，所有最终决策和质量责任由人承担

## 八、电梯演说

大家好，我们做的是"活动通"——一个校园活动一站式管理平台。现在学生找活动要翻好几个群，报名要填好几个问卷，签到还要排队点名，特别麻烦。我们的平台把这些全整合到一起：学生打开手机就能看到所有活动，一键报名，到现场扫个码就签到；社团发活动、管报名、看数据也都在一个后台搞定。我们先从班级试点开始，再推广到全校，让校园活动更简单高效。
